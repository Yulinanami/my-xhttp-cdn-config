# XHTTP + CDN 搭建指南 (六)：拓展 - 上下行不同 CDN

在已有配置上增加一个新模式：

```text
上行 xhttp+TLS+CDN-A | 下行 xhttp+TLS+CDN-B
```

---

## 1. Cloudflare 设置

CDN-A 和 CDN-B 都需要：

- DNS 记录开启代理（橙色云朵）
- SSL/TLS 加密模式：完全（严格）
- Network 里开启 gRPC

如果 CDN-A 和 CDN-B 是同一个域名的 DNS 记录，只需要配置一次即可。

---

## 2. 证书

Nginx 需要能用同一张证书响应这些 CDN 域名。

假设：

```text
Reality 域名: reality.example.com
原 CDN 域名: cdn.example.com
CDN-A: cdn-a.example.com
CDN-B: cdn-b.example.com
```

重新签发证书时执行：

```bash
systemctl stop nginx 2>/dev/null || true

acme.sh --issue \
  -d reality.example.com \
  -d cdn.example.com \
  -d cdn-a.example.com \
  -d cdn-b.example.com \
  --standalone \
  --keylength ec-256

acme.sh --install-cert -d reality.example.com --ecc \
  --key-file /etc/ssl/private/private.key \
  --fullchain-file /etc/ssl/private/fullchain.cer \
  --reloadcmd "systemctl restart nginx"
```

如果 VPS 使用 IPv6 申请证书执行：

```bash
systemctl stop nginx 2>/dev/null || true

acme.sh --issue \
  -d reality.example.com \
  -d cdn.example.com \
  -d cdn-a.example.com \
  -d cdn-b.example.com \
  --standalone \
  --listen-v6 \
  --keylength ec-256

acme.sh --install-cert -d reality.example.com --ecc \
  --key-file /etc/ssl/private/private.key \
  --fullchain-file /etc/ssl/private/fullchain.cer \
  --reloadcmd "systemctl restart nginx"
```

---

## 3. Nginx 配置

CDN-A、CDN-B 分别使用独立回落网站或 `/var/www/dist/<域名>` 目录，你需要上传补充新域名的回落静态 html 页面。

编辑 `/etc/nginx/nginx.conf`，找到原 CDN 的 `server` 块，把 CDN-A / CDN-B 分别写成独立的 `server` 块。

每个 CDN `server` 都要两段：`location /` 回落，`location /your-xhttp-path` 转到 Xray。原 CDN 块不用改路径，只给 CDN-A / CDN-B 各加一块。

```nginx
server {
    listen       127.0.0.1:8003 ssl;
    http2        on;
    server_name  cdn-a.example.com;

    ssl_certificate /etc/ssl/private/fullchain.cer;
    ssl_certificate_key /etc/ssl/private/private.key;

    location / {
        proxy_pass https://www.stanford.edu;
        proxy_ssl_server_name on;
        proxy_ssl_name www.stanford.edu;
        proxy_redirect http://www.stanford.edu/ https://$host/;
        proxy_redirect https://www.stanford.edu/ https://$host/;
        proxy_set_header Host www.stanford.edu;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
    }

    location /your-xhttp-path {
        grpc_pass 127.0.0.1:8001;
        grpc_set_header Host                  $host;
        grpc_set_header X-Real-IP             $real_client_ip;
        grpc_set_header Forwarded             $proxy_add_forwarded;
        grpc_set_header X-Forwarded-For       $proxy_add_x_forwarded_for;
        grpc_set_header X-Forwarded-Proto     $scheme;
    }
}

server {
    listen       127.0.0.1:8003 ssl;
    http2        on;
    server_name  cdn-b.example.com;

    ssl_certificate /etc/ssl/private/fullchain.cer;
    ssl_certificate_key /etc/ssl/private/private.key;

    location / {
        proxy_pass https://www.princeton.edu;
        proxy_ssl_server_name on;
        proxy_ssl_name www.princeton.edu;
        proxy_redirect http://www.princeton.edu/ https://$host/;
        proxy_redirect https://www.princeton.edu/ https://$host/;
        proxy_set_header Host www.princeton.edu;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
    }

    location /your-xhttp-path {
        grpc_pass 127.0.0.1:8001;
        grpc_set_header Host                  $host;
        grpc_set_header X-Real-IP             $real_client_ip;
        grpc_set_header Forwarded             $proxy_add_forwarded;
        grpc_set_header X-Forwarded-For       $proxy_add_x_forwarded_for;
        grpc_set_header X-Forwarded-Proto     $scheme;
    }
}
```

用本地静态页面时，把对应块的 `location /` 换成：

```nginx
    location / {
        root /var/www/dist/cdn-a.example.com;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
```

检查 Nginx 配置并重启 Nginx：

```bash
nginx -t
systemctl restart nginx
```

## 4. Xray 服务端

Xray 服务端不用新增入站。

继续使用原来的 XHTTP 入站即可：

```json
{
  "listen": "127.0.0.1",
  "port": 8001,
  "protocol": "vless",
  "streamSettings": {
    "network": "xhttp",
    "xhttpSettings": {
      "path": "/your-xhttp-path",
      "mode": "auto"
    }
  }
}
```

## 5. Mihomo 客户端配置

复制原来的 `xhttp+TLS+H2` 节点配置，进行如下修改：

```yaml
  - name: 上行 xhttp+TLS+CDN-A | 下行 xhttp+TLS+CDN-B
    type: vless
    server: cdn-a.example.com
    port: 443
    uuid: YOUR_UUID2
    udp: true
    flow: ""
    tls: true
    network: xhttp
    alpn:
      - h2
    servername: cdn-a.example.com
    client-fingerprint: chrome
    encryption: YOUR_VLESS_ENCRYPTION
    xhttp-opts:
      host: cdn-a.example.com
      path: /your-xhttp-path
      mode: auto
      reuse-settings:
        max-concurrency: "16-32"
        c-max-reuse-times: "0"
        h-max-reusable-secs: "1800-3000"
      download-settings:
        host: cdn-b.example.com
        path: /your-xhttp-path
        server: cdn-b.example.com
        port: 443
        tls: true
        alpn:
          - h2
        servername: cdn-b.example.com
        client-fingerprint: chrome
        reality-opts: { public-key: "" }
        reuse-settings:
          max-concurrency: "16-32"
          c-max-reuse-times: "0"
          h-max-reusable-secs: "1800-3000"
```

如果原节点有 xpadding，也要把这些字段也复制到 `xhttp-opts` 和 `download-settings` 里：

```yaml
      x-padding-obfs-mode: true
      x-padding-key: "x_padding"
      x-padding-header: "Referer"
      x-padding-placement: "queryInHeader"
      x-padding-method: "tokenish"
```

选择复用 ECH 时，把 `ech-opts` 复制到上行节点配置和下行 `download-settings` 里。

## 6. v2rayN / Xray 客户端配置

客户端配置和 `xhttp+TLS+H2` 节点一样，把上行地址改成 CDN-A，再在 `extra` 里加入 CDN-B 的 `downloadSettings`。

`downloadSettings` 示例：

```json
{
  "downloadSettings": {
    "address": "cdn-b.example.com",
    "port": 443,
    "network": "xhttp",
    "security": "tls",
    "tlsSettings": {
      "serverName": "cdn-b.example.com",
      "allowInsecure": false,
      "alpn": [
        "h2"
      ],
      "fingerprint": "chrome"
    },
    "xhttpSettings": {
      "host": "cdn-b.example.com",
      "path": "/your-xhttp-path",
      "mode": "auto"
    }
  }
}
```

使用 xpadding 时，要把 xpadding 配置同步放进上行 `extra` 和下行 `downloadSettings.xhttpSettings.extra`。

使用 ECH 时，上行 TLS 和下行 `tlsSettings` 都要加上 ECH 配置。

---

## 7. 缓存绕过规则

根据加入的新域名的数量 修改Cloudflare Cache Rules：

```text
(http.host eq "cdn.example.com") or (http.host eq "cdn-a.example.com") or (http.host eq "cdn-b.example.com") or (http.request.uri.path contains "/your-xhttp-path")
```

缓存资格设置为：

```text
绕过缓存
```
